# 共有先制御（Visibility Control）設計書

## 1. 概要

### 設計の三層

| 層                            | 制御内容                                                                                   | 場所                               |
| ----------------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------- |
| ゴーストモード（How）         | スコープ別に位置の精度を制御（通常/フリーズ/あいまい）+ 緊急オフ（グローバルキルスイッチ） | サーバー                           |
| 可視性チャネル（Who can see） | フレンド関係 or グループ所属で潜在的に見える相手を決定                                     | サーバー                           |
| ビューフィルタ（What I see）  | 地図・タイムラインで **自分が見たい対象** を絞り込む                                       | クライアント（ブラウザストレージ） |

重要な区別:
- **可視性チャネル** はサーバー側で「誰のデータを返すか」を決定する（セキュリティ境界）
- **ビューフィルタ** はクライアント側で「受け取ったデータのうち何を表示するか」を決定する（UX）
- ゴーストモード `off`（緊急オフ）は **グローバルキルスイッチ** — 全スコープに優先して全員に非表示

---

## 2. スコープ

### 実装するもの

1. **グループ機能** — 無線チャンネル型の軽量グループ
2. **パーコンテキスト・ゴーストモード** — フレンド/グループ別に精度を設定
3. **ビューフィルタ** — 地図・タイムラインの表示対象をクライアント側で絞り込み
4. **可視性の拡張** — フレンド以外にも「同グループメンバー」を表示対象に追加

---

## 3. グループ（無線チャンネルモデル）

### 3.1 コンセプト

グループは **FiveM のラジオ無線番号のようなもの** である。

- 最初の1人がグループ名（＋任意でパスワード）を指定して作成
- 他のプレイヤーはグループ名（＋パスワード）を入力して参加
- **誰でも自由に退出**でき、最後の1人が抜けたらグループは自動解散
- 作成者に特別な権限はない（作成後は全メンバーが対等）
- フレンド関係がなくても同じグループに参加可能

### 3.2 グループの性質

| 項目     | 説明                                                           |
| -------- | -------------------------------------------------------------- |
| 識別     | グループ名がユニーク識別子（大文字小文字を区別しない）         |
| 所有者   | なし（作成者が抜けても何も変わらない）                         |
| 参加条件 | グループ名を知っている（＋パスワードが設定されていれば一致）   |
| 退出     | いつでも自由                                                   |
| 解散     | メンバーが0人になった時点で自動削除                            |
| 可視性   | 同グループのメンバー同士は位置が見える（ゴーストモード適用後） |

### 3.3 制約

| 項目                      | 制限値            | 理由                                 |
| ------------------------- | ----------------- | ------------------------------------ |
| グループ名                | 2～20文字         | 短すぎると衝突、長すぎるとUI表示困難 |
| パスワード                | 0～20文字（任意） | 設定なしも許可                       |
| 1プレイヤーの同時所属数   | 5                 | メモリ・クエリ負荷を考慮             |
| 1グループの最大メンバー数 | 50                | サーバー負荷を考慮                   |

### 3.4 ライフサイクル

```
作成 ──→ 稼働中 ──→ 自動解散
 │         │
 │   [メンバー参加/退出]
 │         │
 │         ↓ メンバー0人
 │         └──→ グループ行を DELETE
 │
 └─ グループ名(+PW)を指定して INSERT
```

### 3.5 操作一覧

| 操作         | 説明                                                    |
| ------------ | ------------------------------------------------------- |
| 作成         | グループ名＋任意パスワードを指定。同名が既存→参加扱いに |
| 参加         | グループ名＋パスワードで参加。パスワード不一致→エラー   |
| 退出         | 自分をメンバーから削除。最後の1人なら→グループ自動削除  |
| メンバー一覧 | 同グループの現メンバーを一覧表示                        |

**作成者権限は不要** — 名前変更・強制退出・削除はない。

### 3.6 ブロックとの関係

- AがBをブロックしている場合、同グループに居ても **互いの位置は見えない**
- ブロック関係はグループメンバーシップより優先される
- グループからの自動退出は行わない（ブロックはあくまで可視性フィルタ）
- ただし **チェックイン投稿（タイムライン）にはブロックを適用しない**
    - 理由: チェックインはリアルタイム追跡ではなく、投稿時点のスナップショット情報のため
    - 適用範囲: `getTimeline` / `reactToPost` の可視判定はブロック無視、`getFriendsMap` など位置可視性は従来通りブロック優先

## 4. パーコンテキスト・ゴーストモード

### 4.1 コンセプト

- フレンドには正確な位置を見せたいが、グループには大まかにしたい
- あるグループには通常公開、別のグループにはフリーズで固定位置にしたい

こうした使い分けが可能になる。

### 4.2 モード定義

| モード   | 説明                               | 備考                           |
| -------- | ---------------------------------- | ------------------------------ |
| `normal` | 位置をリアルタイムに正確に返す     | デフォルト                     |
| `freeze` | モード設定時点の座標を固定して返す | フリーズ位置はスコープ別に保持 |
| `blur`   | 座標をグリッド単位で丸めて返す     |                                |

**`off`（緊急オフ）はスコープ別ではなくグローバルキルスイッチ**:
- 緊急オフを有効にすると、全スコープ・全チャネルで一律に非表示になる
- グループだけオフにしたい場合は退出すればよい（軽量なラジオチャンネルモデルなので再参加も容易）
- 緊急オフは `locshare_players.ghost_mode` カラムで管理する（`'off'` のとき全非表示）

### 4.3 データモデル

#### フレンド向けゴーストモード

`locshare_players` テーブルに保持:

```sql
friend_ghost_mode  ENUM('normal','freeze','blur') NOT NULL DEFAULT 'normal',
friend_frozen_x    FLOAT NULL,    -- フリーズ時の固定座標
friend_frozen_y    FLOAT NULL,
friend_frozen_z    FLOAT NULL,
```

#### グループ向けゴーストモード

`locshare_group_members` テーブルに保持:

```sql
ghost_mode  ENUM('normal','freeze','blur') NOT NULL DEFAULT 'normal',
frozen_x    FLOAT NULL,    -- フリーズ時の固定座標
frozen_y    FLOAT NULL,
frozen_z    FLOAT NULL,
```

各グループメンバーシップごとに「自分がこのグループのメンバーにどう見られたいか」を設定する。

### 4.4 可視性判定ルール（パーコンテキスト対応版）

この判定ルールは **リアルタイム位置共有**（地図・近距離通知）に対して適用する。
チェックイン投稿（タイムライン）の可視性判定は別ルールとし、ブロック状態を考慮しない。

プレイヤーAがプレイヤーBの位置を見るときの判定:

```
1. ブロックチェック
   A→Bがblocked OR B→Aがblocked → ❌ 非表示

2. グローバルキルスイッチ（B側）
   B.ghost_mode == 'off' → ❌ 非表示

3. 可視性チャネル収集（OR条件: いずれか成立で可視）
   a. フレンドチャネル: A↔B が相互 accepted
      → ghost = B の friend_ghost_mode
   b. グループチャネル: A と B が同一グループ G に所属
      → ghost = B の G における ghost_mode（group_members の値）
   いずれも不成立 → ❌ 非表示

4. 最緩和ルール（Most Permissive）
   ステップ3 で収集した全スコープの ghost_mode のうち、
   最も緩い（精度が高い）ものを適用する。

   緩い順: normal > blur > freeze
     - normal が1つでもあれば → normal（正確な位置）
     - normal なし & blur あり → blur（グリッド丸め）
     - 全て freeze → freeze（固定座標を返す）

5. フリーズ座標の選択
   最終結果が freeze の場合、フリーズ座標はどのスコープのものを使うか:
   → 最も最近にフリーズが設定されたスコープの座標を使用する
```

### 4.5 最緩和ルールの設計根拠と他案

**採用案: 最緩和ルール（Most Permissive）**

> Bがフレンドに正確な位置を見せる意思がある以上、
> グループ設定がそれを制限する理由はない。

具体例:
- Aが Bob のフレンド、かつ同グループ1に所属
- Bob: フレンドスコープ = `normal`, グループ1 = `blur`
- → Aには `normal`（正確な位置）を表示

**他案1: 最厳格ルール（Most Restrictive）**

全スコープの中で最も厳しい設定を適用する。
- 厳しい順: freeze > blur > normal
- Bob: フレンドスコープ = `normal`, グループ1 = `blur` → Aには `blur` を適用

分析: フレンドに正確な位置を見せたくても、グループ設定 blur が足を引っ張る。
グループ所属を意識して常にフレンド設定を上げる必要があり、UXが直感的でない。

**他案2: スコープ独立表示**

ビューフィルタで見ているスコープの設定をそのまま適用する。
- フレンドフィルタで見ている → フレンドスコープの設定で表示
- グループ1フィルタで見ている → グループ1スコープの設定で表示

分析: フィルタ「全員」で見ている場合にどちらを使うか不明確。
同一人物がフィルタ切替でチラつく。実装が複雑になる。

### 4.6 具体的な評価例

| Bのフレンドモード | Bのグループ1モード | Aから見たB（最緩和）                           |
| ----------------- | ------------------ | ---------------------------------------------- |
| normal            | blur               | **normal**                                     |
| blur              | freeze             | **blur**                                       |
| freeze            | freeze             | **freeze**（最終フリーズ時刻が新しい方の座標） |
| normal            | freeze             | **normal**                                     |
| blur              | normal             | **normal**                                     |

## 5. 可視性チャネル（サーバー側: 誰のデータを返すか）

### 5.1 可視性の判定フロー（まとめ）

```
プレイヤーA が プレイヤーB の位置を見るとき:

1. B→A or A→B がブロック → ❌
2. B.ghost_mode == 'off'（緊急オフ） → ❌
3. チャネル収集:
   - A↔B 相互フレンド → B.friend_ghost_mode を収集
   - A,B が同グループ G → B の G 向け ghost_mode を収集
   - どちらも不成立 → ❌
4. 収集した ghost_mode のうち最も緩いものを適用
5. 精度変換: normal→そのまま / freeze→固定座標 / blur→グリッド丸め
```

**実装上の補足**: グループ経由で可視性が成立するプレイヤーのうち、  
`getActiveState` が nil を返す場合（参加直後で未同期 / 初回位置未受信の状態）は、  
`Runtime.playerLastKnown` の最終既知座標（`x/y/z`）をフォールバックとして使用し  
オフライン扱いで表示する（`isOnline = false`）。  
こうすることで初回参加直後のプレイヤーが地図から消える問題を解消している。

### 5.2 レスポンスに含めるメタデータ

サーバーは各プレイヤーのデータに **可視性チャネル情報** を付与して返す:

```typescript
interface VisiblePlayer {
  playerId: string;
  displayName: string;
  isOnline: boolean;
  x: number; y: number; z: number;
  heading: number;
  speed: number;
  ghostMode: string;       // 最緩和ルール適用後の結果
  moveStatus: string;
  updatedAt: number;

  // 可視性チャネル情報
  isFriend: boolean;              // フレンド関係で見えているか
  sharedGroupIds: number[];       // 共有しているグループIDの配列
}
```

この情報により、クライアント側でフィルタが可能になる。

## 6. ビューフィルタ（クライアント側: 何を表示するか）

### 6.1 コンセプト

サーバーから受け取った「見える可能性のある全プレイヤー」のうち、
**自分が今見たい対象だけを地図・タイムラインに表示する** フィルタ。

これはプライバシー制御ではなく **UX の絞り込み** であり、サーバーに送信する必要はない。

### 6.2 フィルタモード

| モード       | 説明                                                          |
| ------------ | ------------------------------------------------------------- |
| `all`        | 全員を表示（デフォルト）                                      |
| `friends`    | フレンドのみ表示（`isFriend == true`）                        |
| `group:<id>` | 指定グループのメンバーのみ表示（`sharedGroupIds` に含まれる） |

### 6.3 永続化

- **ブラウザの localStorage** に保存
- キー: `whereareyou:viewFilter`
- 値: `{ filter: 'all' | 'friends' | 'group', groupId: number | null }`
- サーバーには保存しない（端末固有の表示設定）
- アプリ再起動時に復元される

### 6.4 フィルタ適用の疑似コード

```typescript
function applyViewFilter(players: VisiblePlayer[], filter: ViewFilter): VisiblePlayer[] {
  switch (filter.mode) {
    case 'all':
      return players;
    case 'friends':
      return players.filter(p => p.isFriend);
    case 'group':
      return players.filter(p => p.sharedGroupIds.includes(filter.groupId!));
  }
}
```

### 6.5 フィルタUIの配置

地図画面（S02）のヘッダーまたはサブヘッダーにドロップダウン/ピルで配置:

```
┌─────────────────────────────┐
│ WhereAreYou?                │
│ [ゴースト ⚙] 表示:[全員 ▼]   │  ← ビューフィルタ
├─────────────────────────────┤
│         （地図）              │
```

ドロップダウン展開時:
```
  ┌──────────────┐
  │ ● 全員        │
  │ ○ フレンドのみ │
  │ ─────────── │
  │ ○ 仲良し (3)  │  ← 所属中のグループが列挙される
  │ ○ レース部 (5) │
  └──────────────┘
```

## 7. 投稿とタイムラインのフィルタ

### 7.1 投稿の帰属

投稿は **投稿者個人に紐づく**。グループに対する投稿という概念はない。

- `locshare_posts` に `visibility` や `group_id` カラムは **不要**
- 投稿の閲覧権限は、投稿者との可視性チャネル（フレンド or 同グループ）で決まる

### 7.2 タイムラインの取得ロジック

```
サーバー側:
1. 「自分が見える全プレイヤー」のIDを取得（§5.1 の可視性判定）
2. そのプレイヤーの投稿を created_at DESC で取得
3. 投稿はスナップショット扱いのため、ブロック関係の投稿は除外しない
4. 各投稿に投稿者の isFriend / sharedGroupIds を付与して返す

クライアント側:
5. ビューフィルタ（§6.2）と同じロジックで投稿を絞り込み・表示
```

### 7.3 タイムラインのフィルタUI

地図のビューフィルタと同じドロップダウンをタイムライン画面にも配置:

```
┌─────────────────────────────┐
│ タイムライン     表示:[全員 ▼] │
├─────────────────────────────┤
│ ...投稿カード...              │
```

## 8. DBスキーマ

```sql
-- プレイヤー情報（位置・ゴーストモード・同意・プロファイルを統合）
CREATE TABLE IF NOT EXISTS locshare_players (
    player_id        VARCHAR(64) PRIMARY KEY,
    -- 位置情報（ランタイム中はメモリ管理、ログアウト時に永続化）
    x                FLOAT NOT NULL DEFAULT 0,
    y                FLOAT NOT NULL DEFAULT 0,
    z                FLOAT NOT NULL DEFAULT 0,
    heading          FLOAT NOT NULL DEFAULT 0,
    speed            FLOAT NOT NULL DEFAULT 0,
    -- ゴーストモード（緊急オフ用グローバルキルスイッチ）
    ghost_mode       ENUM('normal','off') NOT NULL DEFAULT 'normal',
    -- フレンド向けゴーストモード
    friend_ghost_mode ENUM('normal','freeze','blur') NOT NULL DEFAULT 'normal',
    friend_frozen_x  FLOAT NULL,
    friend_frozen_y  FLOAT NULL,
    friend_frozen_z  FLOAT NULL,
    -- プロファイル
    display_name     VARCHAR(128) NOT NULL DEFAULT '',
    -- 同意
    agreed_at        TIMESTAMP NULL,
    -- タイムスタンプ
    updated_at       TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- グループ（無線チャンネルモデル。メンバー0人で自動削除）
CREATE TABLE IF NOT EXISTS locshare_groups (
    id          INT PRIMARY KEY AUTO_INCREMENT,
    name        VARCHAR(50) NOT NULL,           -- グループ名（ユニーク、大小文字無視）
    password    VARCHAR(100) NULL,              -- 任意パスワード
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uq_name (name)
);

-- グループメンバー（パーコンテキスト・ゴーストモードを保持）
CREATE TABLE IF NOT EXISTS locshare_group_members (
    group_id    INT NOT NULL,
    player_id   VARCHAR(64) NOT NULL,
    ghost_mode  ENUM('normal','freeze','blur') NOT NULL DEFAULT 'normal',
    frozen_x    FLOAT NULL,                     -- フリーズ時の固定座標
    frozen_y    FLOAT NULL,
    frozen_z    FLOAT NULL,
    joined_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (group_id, player_id),
    FOREIGN KEY (group_id) REFERENCES locshare_groups(id) ON DELETE CASCADE,
    INDEX idx_player (player_id)
);

-- チェックイン投稿（投稿者個人に紐づく。公開範囲は可視性チャネルで判定）
CREATE TABLE IF NOT EXISTS locshare_posts (
    id          INT PRIMARY KEY AUTO_INCREMENT,
    player_id   VARCHAR(64) NOT NULL,
    x           FLOAT        NOT NULL,
    y           FLOAT        NOT NULL,
    z           FLOAT        NOT NULL,
    content     TEXT,
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_player_created (player_id, created_at)
);

-- リアクション
CREATE TABLE IF NOT EXISTS locshare_reactions (
    id          INT PRIMARY KEY AUTO_INCREMENT,
    post_id     INT          NOT NULL,
    player_id   VARCHAR(64) NOT NULL,
    stamp       VARCHAR(8)   CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci,  -- 絵文字スタンプ
    message     VARCHAR(100) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci,
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (post_id) REFERENCES locshare_posts(id) ON DELETE CASCADE
);
```

## 9. ランタイムメモリ設計

### 9.1 Server.State の拡張

```lua
Server.State = {
    players = {},           -- [playerId] = PlayerState（既存）
    sourceToPlayerId = {},  -- [source] = playerId（既存）
    lastKnownNames = {},    -- [playerId] = displayName（既存）
    nearbyCooldowns = {},   -- [key] = timestamp（既存）
    nearbyLoopStarted = false,  -- 既存

    groups = {},            -- [groupId] = { id, name, password, members = { [playerId]=memberData } }
    playerGroups = {},      -- [playerId] = [{ id, name, ghost_mode, frozen_x, frozen_y, frozen_z, joined_at }]

    friendRelations = {},   -- [playerId] = { outgoing = { [targetId]=status }, incoming = { [sourceId]=status } }
    playerLastKnown = {},   -- [playerId] = { ghostMode, x, y, z }
}
```

### 9.2 PlayerState の拡張

```lua
-- players[playerId] の構造
{
    playerId = "license:xxx",
    source = 1,
    x = 0, y = 0, z = 0,
    heading = 0, speed = 0,
    ghostMode = 'normal',              -- グローバルキルスイッチ: 'normal' or 'off'
    friendGhostMode = 'normal',        -- フレンド向けゴーストモード
    friendFrozenX = nil,               -- フレンド向けフリーズ座標
    friendFrozenY = nil,
    friendFrozenZ = nil,
    -- グループ向けゴーストモードは groups[gid].members 経由で参照
}
```

### 9.3 グループメモリ上のゴーストモード

```lua
-- groups[groupId] の構造
{
    id = 1,
    name = "仲良し",
    password = nil,
    members = {
        ["license:aaa"] = {
            ghostMode = 'normal',
            frozenX = nil, frozenY = nil, frozenZ = nil,
        },
        ["license:bbb"] = {
            ghostMode = 'blur',
            frozenX = nil, frozenY = nil, frozenZ = nil,
        },
    }
}
```

### 9.4 メモリロード/同期タイミング

| イベント                    | 処理                                                              |
| --------------------------- | ----------------------------------------------------------------- |
| リソース起動                | DB → メモリ: 全グループ + メンバー（ゴーストモード含む）をロード  |
| プレイヤー接続（bootstrap） | メモリから自分の所属グループ情報 + 各グループの ghost_mode を返す |
| グループ作成/参加/退出      | メモリ更新 → DB書き込み（即時）                                   |
| ゴーストモード変更          | メモリ更新 → DB書き込み（即時）                                   |
| 退出で0人になった場合       | メモリからグループ削除 → DB DELETE                                |

### 9.5 buildVisiblePlayers（パーコンテキスト対応版）

```lua
-- 疑似コード
function Service.buildVisiblePlayers(viewerId)
    local result = {}
    local friendIds = Service.getAcceptedFriendIds(viewerId)
    local groupMemberIds = Service.getGroupCoMembers(viewerId)

    -- フレンド + グループメンバーの和集合（重複除去）
    local candidateIds = mergeSets(friendIds, groupMemberIds)

    for _, targetId in ipairs(candidateIds) do
        if targetId == viewerId then goto continue end

        -- 1. ブロックチェック
        if isBlocked(viewerId, targetId) then goto continue end

        -- 2. アクティブ状態チェック
        local targetState = getActiveState(targetId)
        if not targetState then goto continue end

        -- 3. グローバルキルスイッチ（緊急オフ）
        if targetState.ghostMode == 'off' then goto continue end

        -- 4. スコープ別ゴーストモードを収集
        local scopeModes = {}
        local isFriend = friendSet[targetId] == true
        local sharedGroupIds = getSharedGroupIds(viewerId, targetId)

        if isFriend then
            scopeModes[#scopeModes + 1] = {
                mode = targetState.friendGhostMode,
                frozenX = targetState.friendFrozenX,
                frozenY = targetState.friendFrozenY,
                frozenZ = targetState.friendFrozenZ,
            }
        end
        for _, gid in ipairs(sharedGroupIds) do
            local memberData = groups[gid].members[targetId]
            scopeModes[#scopeModes + 1] = {
                mode = memberData.ghostMode,
                frozenX = memberData.frozenX,
                frozenY = memberData.frozenY,
                frozenZ = memberData.frozenZ,
            }
        end

        if #scopeModes == 0 then goto continue end

        -- 5. 最緩和ルール適用
        local effectiveMode = resolveMostPermissive(scopeModes)

        -- 6. 精度変換
        local x, y, z = applyGhostPrecision(targetState, effectiveMode)

        result[#result + 1] = {
            -- 基本フィールド
            playerId = targetId,
            displayName = getDisplayName(targetId),
            isOnline = true,
            x = x, y = y, z = z,
            heading = targetState.heading,
            speed = targetState.speed,
            ghostMode = effectiveMode.mode,
            moveStatus = calcMoveStatus(targetState.speed),
            updatedAt = targetState.updatedAt,
            -- チャネル情報
            isFriend = isFriend,
            sharedGroupIds = sharedGroupIds,
        }
        ::continue::
    end

    return result
end

-- 最緩和ルール: normal > blur > freeze
local MODE_RANK = { normal = 3, blur = 2, freeze = 1 }
function resolveMostPermissive(scopeModes)
    local best = scopeModes[1]
    for i = 2, #scopeModes do
        if MODE_RANK[scopeModes[i].mode] > MODE_RANK[best.mode] then
            best = scopeModes[i]
        end
    end
    return best
end
```

### 9.6 パフォーマンス考慮

- フレンドのIDセットは既存処理で O(1) ルックアップ可能
- グループメンバーのIDセットは `playerGroups` → `groups[gid].members` で O(グループ数) で取得
- フレンド関係は `friendRelations`（outgoing / incoming）を参照するため双方向ステータス判定もメモリで完結
- オフライン最終既知位置は `playerLastKnown` を参照するため JOIN なしで扱える
- ゴーストモード取得もメモリ上のテーブル参照のみ
- 全てメモリ上で完結するためDB I/Oは発生しない

### 11.1 NUIコールバック（fetchNui）

| コールバック名      | 方向      | ペイロード                                 | レスポンス                                                              |

| `leaveGroup`        | UI→Server | `{ groupId }`                              | `{ ok }`                                                                |

| `setGroupGhostMode` | UI→Server | `{ groupId, mode, freezeCoords? }`         | `{ ok }`                                                                |
| `deletePost`        | UI→Server | `{ postId }`                               | `{ deleted: true }`                                                     |
| `deleteReaction`    | UI→Server | `{ reactionId }`                           | `{ deleted: true }`                                                     |

`setGhostMode` のスコープ指定:
- `{ scope: 'global', mode: 'off' }` — 緊急オフ ON
- `{ scope: 'global', mode: 'normal' }` — 緊急オフ OFF（通常状態に戻す）
- `{ scope: 'friend', mode: 'blur' }` — フレンド向けをあいまいに
- `{ scope: 'group', groupId: 3, mode: 'freeze' }` — グループ3向けをフリーズに
