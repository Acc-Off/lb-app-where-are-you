# 座標と地図（FiveM / lb-phone）

## 目的

FiveMのゲーム内座標を、lb-phoneの地図UI上で正しく表示するための基準をまとめる。

---

## 1. 参照元

- lb-phone本体の地図実装（Leaflet + カスタムCRS）

---

## 2. Los Santos の基準定数

UI地図の座標変換で使う基準値。

- 地図画像解像度: `16384 x 24576`
- ワールド左上: `x = -4140, y = 8400`
- ワールド右下: `x = 4860, y = -5100`

この範囲外はLos Santos地図に表示しない、または別マップ判定へ回す。

---

## 3. 変換の考え方

### 3.0 座標系の関係（重要）

- 表示先の地図座標系は Leaflet のタイル座標系（tile server の `{z}/{x}/{y}`）
- ただし入力は FiveM のゲーム座標 `(x, y)`
- そのため実装では「ゲーム座標 -> Leafletが扱える座標（CRS） -> タイル取得」の順で変換される

注意点:

- FiveM座標とタイルの `{x}/{y}` は同じ値ではない
- `{x}/{y}` はズーム `z` ごとのタイルインデックス
- CRS設定（`topLeft`, `bottomRight`, `image`）が、ゲーム座標をタイル座標系へ写像する役割を持つ

実装イメージ:

1. FiveM座標 `(x, y)` を正規化
2. CRS変換で Leaflet の内部座標へ写像
3. Leaflet が現在ズームに応じて必要タイル `{z}/{x}/{y}` を tile server へ要求

### 3.1 正規化

ゲーム座標 `(x, y)` を 0〜1 の正規化座標 `(u, v)` に変換する。

$$
 u = \frac{x - x_{min}}{x_{max} - x_{min}}
$$

$$
 v = \frac{y_{max} - y}{y_{max} - y_{min}}
$$

- `u`: 左から右へ増加
- `v`: 上から下へ増加（Y軸反転を含む）

### 3.2 UIピクセル座標化

正規化座標を画像ピクセルに落とす。

$$
 px = u \cdot imageWidth
$$

$$
 py = v \cdot imageHeight
$$

### 3.3 逆変換（必要時）

マップクリック位置からゲーム座標を復元する場合。

$$
 x = x_{min} + u \cdot (x_{max} - x_{min})
$$

$$
 y = y_{max} - v \cdot (y_{max} - y_{min})
$$

---

## 4. 実装方針（推奨）

### 4.1 どこで変換するか

- サーバー: 生のゲーム座標を保持
- UI: 地図描画時に変換
- 例外: プライバシー処理（あいまい化）はサーバー側で先に適用してから配信

### 4.2 データフロー

1. Client Lua がプレイヤー座標を取得してサーバー送信
2. Server Lua がフレンドごとの表示用座標を返却
3. UI(React) が座標を変換して Leaflet マーカー描画

### 4.3 モード別扱い

- 通常公開: 最新座標をそのまま変換
- フリーズ: モード切替時点の固定座標を返す
- あいまい: グリッド丸め後の座標を返す
- 緊急オフ: 一覧から除外

---

## 5. あいまい化の実装例

サーバー側で丸める。

- グリッド幅を `grid = 80.0`（要調整）
- 以下で丸める

```lua
local function blurCoord(value, grid)
    return math.floor((value / grid) + 0.5) * grid
end
```

注意:
- 共有先が多い場合も同じ丸め結果を使う
- 表示だけ丸めるのではなく、配信データ自体を丸める

---

## 6. 失敗しやすいポイント

- Y軸反転漏れで上下が逆になる
- `xMin/xMax/yMin/yMax` の取り違えで斜めにズレる
- マップ境界外の座標をそのまま描画してアイコン消失
- タイル設定不一致（`maxZoom`, `noWrap`）でズーム時にズレる
- 端点補間によるチラつき（更新間隔が短すぎる）

## 8. タイルURLの存在とCRS具体値

### 8.1 タイルURLの存在（参照先）

以下は地図実装内で定義されている実際の参照先。

- Los Santos 固定URL
  - `https://assets.loaf-scripts.com/map-tiles/gtav/main/{layer}/{z}/{x}/{y}.jpg`
- Cayo Perico 固定URL
  - `https://assets.loaf-scripts.com/map-tiles/gtav/cayo-perico/{layer}/{z}/{x}/{y}.jpg`
- CustomMaps（サーバー設定由来）
  - `tileServer = e.url`（CustomMaps配列のurlを使用）

### 8.2 CRSの計算ロジック（実装）

地図設定 `image`, `topLeft`, `bottomRight` から以下を生成する。

- `wrapLng = [topLeft.x, bottomRight.x]`
- `wrapLat = [bottomRight.y, topLeft.y]`
- `maxZoom = ceil(log2(max(imageWidth, imageHeight) / 256))`
- `s = 2^maxZoom`
- `gameWidth = bottomRight.x - topLeft.x`
- `gameHeight = bottomRight.y - topLeft.y`
- `u = imageWidth / (gameWidth * s)`
- `d = imageHeight / (gameHeight * s)`
- `Transformation(a,b,c,d2) = (u, -u * topLeft.x, d, -d * topLeft.y)`

### 8.3 Los Santos の具体値

入力:

- `image = [16384, 24576]`
- `topLeft = [-4140, 8400]`
- `bottomRight = [4860, -5100]`

計算結果:

- `wrapLng = [-4140, 4860]`
- `wrapLat = [-5100, 8400]`
- `maxZoom = 7`
- `s = 128`
- `u = 16384 / (9000 * 128) = 0.0142222222`
- `d = 24576 / (-13500 * 128) = -0.0142222222`
- `Transformation = (0.0142222222, 58.88, -0.0142222222, 119.4666667)`

### 8.4 Cayo Perico の具体値

入力:

- `image = [10000, 10000]`
- `topLeft = [3700, -4150]`
- `bottomRight = [5700, -6150]`

計算結果:

- `wrapLng = [3700, 5700]`
- `wrapLat = [-6150, -4150]`
- `maxZoom = 6`
- `s = 64`
- `u = 10000 / (2000 * 64) = 0.078125`
- `d = 10000 / (-2000 * 64) = -0.078125`
- `Transformation = (0.078125, -289.0625, -0.078125, -324.21875)`

### 8.5 CustomMaps の具体値について

CustomMaps は固定値ではなく、サーバーから渡される設定値で決まる。

必要パラメータ:

- `resolution` -> `image`
- `topLeft`
- `bottomRight`
- `url` -> `tileServer`
- `zoom.default`（初期ズーム）

したがって CustomMaps の CRS具体値は「設定ファイル（またはサーバー応答）」ごとに再計算する。

## 9. `misc/minimap` の6枚画像を組み込む案

### 9.1 前提確認

- `docs/misc/minimap` に 6 枚の画像が存在する
- ファイル名:
  - `minimap_sea_0_0.png`
  - `minimap_sea_0_1.png`
  - `minimap_sea_1_0.png`
  - `minimap_sea_1_1.png`
  - `minimap_sea_2_0.png`
  - `minimap_sea_2_1.png`
- 全画像サイズは `3072 x 3072`
- 命名規則だけでは最終配置方向が未確定
- ただし、Los Santos 固定URL と同じ縦横比に合わせるなら、合成サイズは `6144 x 9216` になる必要がある
- これは `2 列 x 3 行` の場合に一致する

補足:

- Los Santos 固定URL の画像比率は `16384:24576 = 2:3`
- world bounds の比率も `9000:13500 = 2:3`
- 6枚画像を `2 列 x 3 行` で並べた場合、`6144:9216 = 2:3` となり一致する
- 逆に `3 列 x 2 行` だと `9216:6144 = 3:2` になり一致しない

### 9.2 結論

タイルサーバーを使わず、ローカル画像を組み込むことは可能。

### 9.3 実装方式（2択）

#### A. ImageOverlay 6枚方式（最短）

- 6枚をそれぞれ `ImageOverlay` で重ねる
- 各画像に対応する world bounds を割り当てる
- メリット: 実装が早い
- デメリット: メモリ負荷が高く、ズーム品質がタイル方式より不安定

#### B. ローカルTileLayer方式（推奨）

- 6枚を事前に `z/x/y` タイルへ変換し、`ui/dist/minimap/...` 配下に配置
- `TileLayer` URL をローカル相対パスに変更
- メリット: 表示品質・負荷・拡張性が高い
- デメリット: 事前タイル化の手間がある

### 9.4 既存座標系との整合

「Los Santos 固定URL」と同じ world bounds を採用するなら、画像素材が変わっても座標系は維持できる。
ただしその前提は、画像全体の縦横比が `2:3` で一致していること。

- world x 範囲: `[-4140, 4860]`（幅 `9000`）
- world y 範囲: `[-5100, 8400]`（高さ `13500`）

2 列 x 3 行で組む場合:

- 1列あたりの world 幅 `tileWorldWidth = 9000 / 2 = 4500`
- `col = 0,1`
- `xMin(col) = -4140 + 4500 * col`
- `xMax(col) = xMin(col) + 4500`

行方向（3分割）:

- 1行あたりの world 高さ `tileWorldHeight = 13500 / 3 = 4500`
- `row = 0,1,2`
- `yMax(row) = 8400 - 4500 * row`
- `yMin(row) = yMax(row) - 6750`

上式は次のように読み替える:

- `yMin(row) = yMax(row) - 4500`

例:

- `row=0, col=0` -> `x:[-4140,360], y:[3900,8400]`
- `row=2, col=1` -> `x:[360,4860], y:[-5100,-600]`

注意:

- 現在のファイル名だけでは `minimap_sea_2_1` が本当に左下か右下かを断定できない
- 実装前に 6 枚を仮合成して向きと配置順を確認すること

### 9.5 実装判断

- 短期検証: A 方式
- 本番運用: B 方式

### 9.5.1 タイル化

- 元画像 6 枚を 1 枚の大画像として扱い、そこから `z/x/y` タイルを生成すればよい
- 想定完成形は `ui/dist/minimap/{layer}/{z}/{x}/{y}.png` のような構成
- Leaflet 側は外部URLの代わりにローカル相対パスを参照する

実務上の流れ:

1. 6枚を正しい順序で仮合成する
2. 合成結果が `2:3` 比率であることを確認する
3. タイル生成ツールまたはスクリプトで `z/x/y` を出力する
4. ローカル `TileLayer` に差し替える

補足:

- 画像が 6 枚とも同一解像度なので、タイル化自体は難しくない
- 一番大事なのは「配置順」と「上下左右の向き」の確定

### 9.6 注意点

- 6枚画像が本当にLos Santos全域と一致するか、固定点3点で必ず検証する
  - 左上基準
  - 中央基準
  - 右下基準
- 元画像の方位（上下反転・左右反転）が異なる場合は、表示時に補正が必要
- 画像縁の継ぎ目が見える場合は 1px オーバーラップまたはタイル化時のパディングで対処

### 9.7 検証結果

2026-03-27 時点で、`docs/misc/tile-convert/output/index.html` を用いた確認では以下が成立した。

- 地図表示に目視上のズレはない
- 地図上の任意点をクリックして取得した `lat/lng` は、実際のゲーム座標と一致した
- `misc/minimap` の 6 枚画像は、Los Santos 固定URL と同じ world bounds 前提で利用可能と判断してよい

この結果により、`misc/minimap` 由来のローカルタイルを本アプリの地図基盤候補として採用できる。
